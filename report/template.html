1. Problem summary

A classifier trained on clean images can lose accuracy when test images contain noise, blur, weather effects or digital artifacts. Tent addresses fully test-time adaptation: adapt a trained model using unlabeled target data, without source data or target labels [1]. This experiment asks whether the released implementation reproduces the Source, Norm and Tent results reported in the authors’ public CIFAR-10-C example [2].

The declared scope is the Standard WRN-28-10 model, all 15 standard CIFAR-10-C corruptions, severity 5, and 10,000 images per corruption. The target is the executable public example. Paper Table 2 uses R-26 and offline adaptation and is contextual evidence rather than the numerical target of this experiment.

2. Method explanation

Tent minimizes the mean prediction entropy over each unlabeled test batch: L(X) = −(1 / |X|) Σx∈X Σc p(c|x) log p(c|x). It estimates BatchNorm statistics from the current batch and optimizes only the channel-wise affine scale and shift, γ and β. The other model parameters are fixed. Ground-truth labels are used only to measure classification accuracy.

Source uses the pretrained model in evaluation mode and its stored normalization statistics. Norm uses target batch statistics without an optimizer update. Tent additionally performs one Adam update per batch, with learning rate 0.001, β1 = 0.9, β2 = 0.999 and zero weight decay. The official online implementation returns predictions computed before the current batch’s parameter update; that update influences later batches. Norm and Tent reset their saved states between corruptions. Source has no adaptation state to reset.

3. Official implementation and experimental protocol

The adaptation and evaluation code comes directly from the official repository at commit e9e926a668d85244c66a6d5c006efbd2b82e83e8. Its source files, YAML configurations and MIT license are included under official/. A SHA-256 manifest verifies that the supplied files match the downloaded snapshot. The experiment invokes the authors’ cifar10c.py directly, which uses their tent.py, norm.py and RobustBench accuracy function. No independent adaptation implementation or adaptation unit-test suite is added in v2.

Project-specific code prepares dependencies, invokes the official command, preserves logs, reads reported percentages and builds tables and this report. This is reuse of the authors’ implementation; the project does not claim an independently implemented entropy objective or optimizer. RobustBench 1.1 supplies the pretrained checkpoint and dataset loader.

The original repository pins a 2021 software stack. The cluster preparation uses the existing modern PyTorch environment from the earlier experiment, adding YACS 0.1.8 and iopath 0.1.8. A compatible fallback requirements file is supplied if that environment is absent. This dependency change is explicit; it does not reproduce the original software environment.

The released YAML evaluates severities 5 through 1. This experiment selects severity 5 through the supported command-line override CORRUPTION.SEVERITY [5]. Primary batch size is 200, RNG seed is 1, and cuDNN benchmarking is enabled. Image order stays fixed because the official loader call uses shuffle=False. Each method runs in a fresh process. An optional batch-128 comparison uses the same official code; it is not an exact recreation of paper Table 2. No shuffled-order experiment is included because the released entrypoint does not expose that setting.

5. Discussion and limitations

The planned comparison holds input conditions fixed across the public example’s three methods. Low prediction entropy measures confidence rather than correctness, so a benefit on this benchmark would not establish improvement on every distribution shift. A single fixed-order run per method does not provide seed-based uncertainty estimates. cuDNN benchmarking and CUDA arithmetic can produce small numerical differences.

Paper Table 2 reports Source/BN/Tent errors of 40.8/17.3/14.3% using R-26, batch 128 and offline adaptation. The public example instead uses WRN-28-10 and online scoring. Matching its public values cannot establish an exact numerical reproduction of the paper’s R-26 experiment.

When measurements are available, the analysis reads the unchanged official program’s per-corruption errors printed to two decimal places and computes their arithmetic mean. Per-image predictions and integer correct counts are not reconstructed from rounded percentages. Process durations include startup, checkpoint and dataset loading, GPU transfers, evaluation and logging. They are not evaluation-loop timings, and v2 does not collect per-method GPU-memory peaks.
